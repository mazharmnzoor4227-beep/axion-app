# Axion — 30-second demo video script

> SCRIPT ONLY. The video has NOT been made. No footage has been shot,
> no screen recording exists, and nothing in this file is a claim that
> the video — or any shot in it — has been produced. When the video is
> shot, every frame must be a real screen recording of the real app on
> the user's real phone, with real data and no staged or mock content.
>
> Story: "I built this app on my phone, free."
> Length: 30 seconds. Format: vertical 9:16, phone screen recording
> with the phone's real UI. Voiceover: the user's own voice, plain and
> unscripted-sounding — read the lines as written, do not improvise
> claims. On-screen text: short, English only, large enough to read on
> a phone.

## Shot list

### 0–5s — The hook: the phone IS the computer

- Visual: phone home screen, then Axion opens. One tap into the
  Terminal; `uname -a` runs and real Ubuntu output appears.
- On-screen text: "No server. This phone is the computer."
- Voiceover: "No server. My phone is the computer."
- Capture note: real terminal, real output. Do not fake the output
  with an overlay.

### 5–12s — Ask it to build an app

- Visual: Ask chat. The user types (or dictates): "Build me a small
  app that tracks my daily expenses." Axion replies and the Build pane
  starts working — files appear, progress is visible.
- On-screen text: "I asked my phone to build an app."
- Voiceover: "I asked my phone to build an app for me."
- Capture note: use a real prompt the user actually wants built. The
  build must be a real build run, recorded live — do not cut to a
  finished project that was built earlier and pretend it happened now.

### 12–18s — The preview: it actually works

- Visual: the built app running in Axion's on-phone preview. Tap
  through it — add an expense, see it listed.
- On-screen text: "It works. On my phone."
- Voiceover: "And it works — right here, on my phone."
- Capture note: the taps must be real and the app must respond. If the
  build fails on camera, stop and fix it; do not cut around a failure
  and pretend it worked.

### 18–24s — Push it to GitHub, from the phone

- Visual: back in chat, Axion commits and pushes; the GitHub repo page
  opens in the in-app browser showing the new commit.
- On-screen text: "Pushed to GitHub. From my phone."
- Voiceover: "Then I pushed it to GitHub — all from my phone."
- Capture note: a real repo, a real push, a real commit on screen. The
  repo must be the user's own. Never show a token or key in this shot.

### 24–30s — The close: free, on your own keys

- Visual: quick montage of the local model answering offline (model
  name visible), then the Axion logo / app name on a clean screen.
- On-screen text: "Free. Your keys. Your phone." then "Axion".
- Voiceover: "Free — on my own keys, on my own phone. This is Axion."
- Capture note: the offline claim is only honest if the local-model
  shot is genuinely recorded with the network off. If that cannot be
  shown, drop the word "offline" from this shot and keep the rest.

## What the video must NOT claim

- No ratings, download numbers, awards, or "best / #1" claims — none
  are verified.
- No Telegram or remote control — Axion is phone-only.
- No release-signed APK — the builder produces a debug APK.
- No tool use by the local model — LFM3 is chat-only.
- No exact-to-the-minute scheduling — do not promise it on camera.

## Production notes

- Shoot on the user's real phone, in one sitting where possible, so
  the build, preview, and push are one continuous true story.
- English UI throughout; English on-screen text only.
- No API keys, tokens, passwords, phone numbers, or email addresses
  visible in any frame. Check every frame before export.
- Keep the voiceover to the lines above — short, plain, and true.
- Total runtime must stay at 30 seconds; trim pauses, never add claims
  to fill time.
- Export vertical 9:16. Keep the raw screen recordings until the final
  cut is approved, so any challenged frame can be re-checked.
